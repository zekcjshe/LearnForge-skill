# 认知范例：系统架构与设计权衡 (system_architecture.md)

## 适用特征
系统架构（微服务 vs 单体）、存储引擎（LSM-Tree vs B+Tree）、并发网络模型（epoll vs io_uring，Go netpoll vs Netty）、分布式一致性（Raft vs Paxos）等具有“没有银弹、只有 Trade-off”的主题。

---

## 教学组织骨架

### 1. 业务规模爆发与经典架构瓶颈
- **痛点场景切入**：例如“高并发读写下关系型数据库磁盘寻道暴增”、“海量短连接导致线程上下文切换打满 CPU”；
- **核心矛盾**：吞吐量 vs 延迟、读放大 vs 写放大、强一致性 vs 高可用性。

### 2. 核心架构机理与演进流
- **极简拓扑图 (Mermaid)**：画出组件分层与数据流向（如 MemTable -> Immutable -> WAL -> SSTable）；
- **关键读写路径追踪**：分别画出“一条写请求如何落地”和“一条读请求如何穿透缓存查到数据”。

### 3. 异构方案权衡矩阵 (Trade-off Matrix)
- 严禁盲目站队，必须提供**横向对比评估表**：
  | 方案/维度 | 适用场景 | 读性能 | 写性能 | 空间利用率 | 运维复杂度 |
  |---|---|---|---|---|---|
  | **方案 A** | ... | ... | ... | ... | ... |
  | **方案 B** | ... | ... | ... | ... | ... |

### 4. 工业级落地缺陷与崩溃案例 ⚠️
- 读放大引发的延迟毛刺与 Bloom Filter 调优；
- 写入堆积触发后台 Compaction 导致 IO 拥塞停顿 (Write Stall)；
- 分布式脑裂与时钟漂移对租约判定的破坏。
